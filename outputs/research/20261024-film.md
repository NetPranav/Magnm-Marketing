## TL;DR
- Strongest provable story: **"It shows you the command before it touches anything."** Developers' #1 fear with AI in the terminal right now is an agent running a destructive command on its own (documented incidents with Claude Code, Gemini CLI, Replit in the last 15 months; 46% of devs distrust AI accuracy). Cero's answer is visible, unedited, on screen: the "Run this command?" dialog with the exact command, a Cancel that really cancels ("Declined in the confirmation dialog"), and Ctrl+C stopping a running request ("Stopped.").
- Best second beat: **"Wrong name? It asks, it does not guess."** (typo "clude" -> claude; "gitbarins" -> "Did you mean gitbrains?").
- The repo's older docs (FEATURES.md, SECURITY.md, FAQ.md) contain claims that contradict the README (robotics, "100% local", "no Ollama", undo log, auto-heal). Use README only. See Do-not-claim.
- Footage: real app text is small at 1920x1080; for 9:16 every terminal shot needs a 2-3x crop. Dialogs crop well. The demo's own title slides must not be reused.

## 4. Candidate film topics (ranked)
### #1 "See it before it runs."  (RECOMMENDED)
- Tension: "I want AI in my terminal, but I've read the stories - agents that `rm -rf` a home folder or a production DB without asking." (W1-W4)
- Cero's proven answer: questions are answered straight from real output; anything that changes files, system or network stops on a dialog showing the exact command; Cancel really cancels; Ctrl+C stops a running request. (F2, F2a, F6, F8)
- Footage proof: demo 8-16 (read-only answer, no dialog) -> 52-55 "Run this command? ... Nothing runs until you approve" -> 56-59 "Declined in the confirmation dialog" -> 82-87 flow "only after you click Run" -> ~108-116 `sleep 40` approved, then Ctrl+C -> "Stopped." Stills: flow-approval.png (5 commands), close-port.png (`kill 12121`, "never asks for your password").
- Why it beats a feature list: one feeling (control), one repeated visual motif (the dialog / the exact command), payoff line writes itself from on-screen text. Works with no VO because the UI text IS the script.
- Risk: approval is not unique (W7). Lean on "exact command, before it runs" + "questions don't need permission" rather than "only Cero asks".
### #2 "It asks. It doesn't guess."
- Tension: AI that confidently acts on a wrong guess (W2, W4 "almost right").
- Proof: 36-43 "clude" -> "claude is running (You wrote "clude"...)"; 44-51 "gitbarins" -> "Did you mean gitbrains?"; F7 "never creates a folder when asked to open one".
- Strong as beat 2 inside #1 (combined arc: "It asks before it guesses. It asks before it acts.").
### #3 "One file. Every command. Your click."  (.flow)
- Tension: setup scripts / onboarding that break or run things you didn't read (W8, W10).
- Proof: 64-78 save as workflow; 82-95 double-click -> list -> Run -> finished; make-workflow.png, flow-approval.png, flow-run.png.
- Weakness: the "runs on any OS" half is only verified on macOS (F13). Any cross-OS visual (three OS logos running the same file) would overclaim. Fine if framed as "one readable file, nothing runs until you click Run".
### #4 "Your terminal, your model."
- Tension: terminal data sent to cloud LLMs (W5, W9).
- Proof: settings.png; "AI: local" in status bar. Static only - no footage of switching models or offline use. Good as a closing line, weak as a whole film.
### #5 "It learns only when you say so."
- Proof: 122-142 /learn, /learned. Niche tension (W: none sourced). Nice colourful shot; use as a detail, not a topic.

## 5. Do NOT claim
1. ROS / robotics / "robotics engineers" (docs/FEATURES.md line 3 says it; README does not; product-facts bans it).
2. Anything LazyLayout.
3. "100% local", "nothing ever leaves your machine", "zero telemetry", "offline-first" as absolutes (docs/FAQ.md, SECURITY.md sec 4). False when a cloud key is chosen. Allowed: "The built-in model and Ollama keep requests on your computer."
4. "No Ollama needed / zero-Ollama", "bundles Qwen... loaded automatically" from FAQ.md/FEATURES.md - stale; README says the model is a choice/download.
5. Undo log / `>undo last step`, auto-heal / `>fix`, "8-category Security Guardian", AST parser, "Zero-Trust", prompt-injection defence, hardware tiers, progress bar %, WebGL "sub-millisecond", "infinite split panes" - only in older docs, not in README. Ask CEO before any.
6. Reliability numbers: README says 85.9% first-try / 0.0% flip on 71 cases; MODEL_RELIABILITY.md shows 83.1% raw and 80.3% / 2.8% flip for the agent path - inconsistent, and below the 95% target. Do not put numbers on screen. "Same answer every time" only as README wording, not as a stat.
7. "Works on Windows and Linux" / "tested on every OS" / visual of a .flow running on three OSes - Linux & Windows builds not yet run on those systems (README 297-306).
8. "Never runs anything without asking" - wrong: read-only commands run without a dialog. Say: "Anything that changes your files, system or network asks first."
9. "Keychain on every OS" - Linux uses a private 0600 file.
10. "Signed / notarized / verified installer" - it is not (README 289-291).
11. The visible queue: real (README 169) but not in footage - do not show a fake queue UI.
12. Do not show the demo clip 56-59 as "folder opened" - it was declined.
13. Do not reuse the demo's slides (0-8, 32-36, 60-64, 78-82, 95-99, 118-122, 142-147.5) or the closing card with the old github.com/NetPranav/Sentinal-Terminal URL. Current repo: github.com/NetPranav/Cero-Terminal (per product-facts; README badges still point to Sentinal-Terminal - CEO to confirm which link to show).
